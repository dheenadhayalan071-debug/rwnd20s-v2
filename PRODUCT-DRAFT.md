## 1. Three categories, nothing else

| Category | Products | Smart-collection rule | Shopify category on each product |

| **Chains** (chains + pendants) | 12 | tag = `chains` | `Apparel & Accessories > Jewelry > Necklaces`, Type = `Chain` |
| **Rings** | 4 | tag = `rings` | `Apparel & Accessories > Jewelry > Rings`, Type = `Ring` |
| **Bracelets** | 4 | tag = `bracelets` | `Apparel & Accessories > Jewelry > Bracelets`, Type = `Bracelet` |
| _Not a category_ — watch / earphones / mystery set | 3 | none (they stay standalone products) | Watches · In-Ear Headphones · Jewelry Sets |

The `rings`, `bracelets` and `chains` collections already exist, so **no new collection is needed** — only the rules above. The `earrings` collection can be deleted; nothing links to it.

Shopify has no "Chains" taxonomy node, so chains are stored as *Necklaces* and labelled *Chain* via Type + tag. That is the correct place in the product taxonomy; the word "Chains" lives in the collection name and the nav.

## 4. How to upload (you do this, I cannot write to admin)

1. Shopify admin → **Products** → **Import**.
2. Choose `products_export_fixed.csv` from the repo root.
3. Tick **"Overwrite any current products that have the same handle"**. Leave "Publish new products" on.
4. Import. Prices, compare-at prices, SKUs, stock counts, images, variants and metafields in the file are unchanged from your export, so nothing gets zeroed.
5. Check 3 products afterwards: *Scarlet Nova* (was `earring-1`, now a chain), *Chrome Link* (was titled "…Earphones (TYPE-C)"), *Chrome Lattice* (was `bracelet 1`).

**What the file changes, per product:** Title, Body (HTML), Vendor (`My Store 2` → `RWND20s`), Product Category, Type, Tags, SEO title + description, and the price-band tag (`under-300`/`-500`/`-600`) re-derived from the actual price.

**What it does not change:** price, compare-at price, SKU, inventory, images, option names/values, handles. Handles stay because renaming a handle through CSV import creates a *new* product and strands the old URL.
